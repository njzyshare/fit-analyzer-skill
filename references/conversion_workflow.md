# FIT 运动文件互转流程规范（佳明 ↔ 高驰）

> **适用**：把一条运动记录从佳明设备换成高驰设备身份（或反向），要求产物**符合 FIT 标准**
> 且能被目标平台正常识别、正常计算派生指标（最快 1KM / 最佳配速 / 训练效果等）。
>
> **本文是流程总纲**；字段级细节见 `field_mapping_garmin_to_coros.md`；
> 官方定义见 `fit_profile_official.json`（由 `@garmin/fitsdk` v21.214 导出）。

---

## 一、总原则（三条，缺一不可）

### 原则 1：一切以 FIT 官方定义为准

字段号、`scale`、`offset`、`fitBaseTypeId` 四样必须对齐。

> 🔴 **字段号绝不允许靠记忆。** 我在此栽过多次：
> - 把 `f73`（enhancedSpeed 速度）当海拔 → 算出 6000 米假海拔
> - 把 `f78`（stanceTimePercent）当速度
> - 以为 record 的温度是 `f53`（实为 fractionalCadence），真值是 `f13`

**动作**：写任何映射前，先查 `fit_profile_official.json`。

### 原则 2：真的照抄目标平台真机的写法

FIT 是标准，但各家有**私有约定**（类型码选择、消息顺序、非标消息、渐进布局等）。
这些约定**不看真机就不知道**，且**可能影响 APP 的派生指标计算**。

**动作**：拿目标平台的真机文件，逐消息、逐 DEF、逐类型码比对，差异点全部复刻。

### 原则 3：绝不编造数据

> **没有数据来源的字段，一律留无效哨兵。永不填推测值、经验值、气候值、平均值。**

"真机有这个值" ≠ "我必须有这个值"。真机的值来自它自己的传感器 / App / 云服务，拿不到就是拿不到。

**自检**：写每个字段前问「这个值的原始来源是什么？」
- 源文件某字段 → ✅ 可搬（注意 scale/offset）
- 能从源数据确定性推导 → ✅ 可算
- **"大概是"/"按经验应该是"/"按月份应该是" → ❌ 禁止**

## 二、标准作业流程（七步）

### Step 0　准备

```bash
# 工作目录五分离，不污染其他位置
<work>/_input/    源文件（.fit / .zip）
<work>/_work/     中间产物
<work>/_tmp/      一次性脚本与调试输出
<work>/_scripts/  正式脚本
<work>/output/    最终交付
```

需要三个参照：
1. **目标平台真机文件**（最重要，决定"照抄什么"）
2. 源文件
3. 官方 profile（`references/fit_profile_official.json`）

### Step 1　读官方定义，列字段映射表

先确定**目标平台用哪些消息**（通常是 `fileId / deviceInfo / activity / event / record / fieldDescription / developerDataId / lap / session`），
逐字段查官方名 + scale + offset + 类型，写出映射表（源字段 → 目标字段 → 换算）。

**输出物**：映射表（可直接写进脚本注释）。

### Step 2　逐字节比对真机，找"非官方写法"

用 `scripts/fit_vs_official.py` + 手工比对，重点看：

| 比对项 | 怎么比 |
|---|---|
| 文件头 | protocol / profile version / dataSize / magic / CRC |
| 消息集合 | global 号集合与各自条数 |
| **DEF 布局序列** | 每个 global 有几种 DEF？字段顺序？有无渐进写法？ |
| **字段类型码** | 逐字段 `fitBaseTypeId` 是否一致 |
| 开发字段 | 206/207 的声明次数、local 号、`fieldDefinitionNumber` |
| 消息顺序 | 谁在谁前面（如 206 必须在 record 的 dev 字段之前）|

**输出物**：「高驰非官方写法清单」（本文的姊妹章节）。

### Step 3　写转换脚本

按映射表 + 非官方写法清单实现。要点：
- 自行拼字节，**不要用 `@garmin/fitsdk` 的 Encoder**（它按佳明 profile 写，产出不符合高驰规范）
- 用**固定的 local 分配表**（本项目 9 个 layout → local `0..8`），全程不回绕
- 派生量（lap 均速、最大速度、最小心率等）从 record 流按时间窗推导
- 哨兵值**按类型码**选（见下）

### Step 4　哨兵与零值的正确姿势

**无效哨兵按类型码选**，不能一律 `0xFF`：

| 类型 | 哨兵 | 误填 0xFF 的后果 |
|---|---|---|
| `U8`/`U16`/`U32` | `0xFF`/`0xFFFF`/`0xFFFFFFFF` | ✅ |
| **`S8`** | **`0x7F`（127）** | 读成 -1 / 255（高驰显示 255℃）|
| `S16`/`S32` | `0x7FFF`/`0x7FFFFFFF` | 读成 -1 |

**零是有效值**（宁死不能丢）：
- `speed == 0` 是暂停/静止，高驰靠它算移动时间 → 最快 1KM
- 代码里**禁用 `if v:`**，必须 `if v is not None:`
- **禁止对速度做平滑**：源速率已是设备融合结果，平滑会把 0 抹掉

### Step 5　重建并校验（七道）

```bash
python scripts/fit_verify_coros.py <产物.fit> <源.fit> [真机模板.fit]
```

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 完整解析 | 解析字节数 == 数据区大小 |
| 2 | protocol | == 真机值（高驰 32）|
| 3 | DEF 布局 | 与真机逐位一致（含渐进式）|
| 4 | 物理量 | 海拔个位数、配速 4~7 分、步频 160~180、温度不是 127/255 |
| 5 | **零值点** | `speed==0` 点数与源相当 |
| 6 | 开发字段 | dev16 存在且含 0 值 |
| 7 | **CRC** | 头部 + 整文件都 ✅ |

再补两道：
- **官方 SDK 解码**：`@garmin/fitsdk` 能否 **0 error**
- **逐字节回比**：关键字段（海拔/速度/心率）与源逐点比对，最大差异应为 0

### Step 6　交付与沉淀

- 产物放统一目录，记录 md5
- **把本轮新发现的差异追加到规范文档**
- 临时文件清理

## 三、已知的高驰私有写法（持续补充）

| # | 项 | 高驰写法 | 备注 |
|---|---|---|---|
| 1 | protocol | **32** | 佳明 16 |
| 2 | profile version | **21158** | |
| 3 | 类型码 | ~~高驰把经纬度写成 `0x00`~~ **【已证伪】** 查模板 `base_type` 即可，两家都与官方一致 |
| 4 | **record 渐进式布局** | 前 9 条从少到多 | 见下 |
| 5 | `fieldDescription` | **声明 2 次**（local 0 / 8）| |
| 6 | 无 `file_creator` / 独立 `sport` / `gpsMetadata` | — | 精简 |
| 7 | lap `f19` = avgPower | 不是垂直振幅 | |
| 8 | 温度 | 真机自己测/写；源无则**留无效**（绝不编）| |

### record 渐进式布局细节

高驰同一段 record 用 **6 种 DEF**：

```
[42,253,5]                                         ×1
[42,253,0,1,5,3]                                   ×2
[42,253,0,1,5,3,6,41,39,83]            + dev16     ×2
[42,253,0,1,5,3,2,6,41,39,83]          + dev16     ×2
[42,253,0,1,5,3,2,6,7,29,41,39,83,85]  + dev16     ×2
[42,253,0,1,5,3,2,6,4,7,29,41,39,83,85]+ dev16     ×余下
```

推断语义：**逐段声明"这些字段从这一刻起才有值"**。

## 四、反面教材（每条都实际踩过）

| 错误 | 后果 | 教训 |
|---|---|---|
| 字段号靠记忆 | 6000 米假海拔 | 查官方 profile |
| 以为 enhanced 字段和基础字段同号 | 漏掉真值（基础常无效）| enhanced 优先 |
| 平滑速度 | 暂停的 0 被抹 → 无最快 1KM | 禁平滑 |
| 差分优先于源速率 | 起跑被抬高、暂停被掩盖 | 信源 |
| `if spd_ms:` | 0 被当假值丢 | 用 `is not None` |
| **编造温度/触地值** | **伪造数据（最严重）** | **绝不编造** |
| 哨兵一律 0xFF | S8 读成 255℃ | 按类型码选 |
| 写死一套 DEF 布局 | 换型号即失效 | 从模板读渐进节奏，逐段复刻 |
| 手工拼 DEF 漏 reserved 字节 | 解析崩（g=768）| 结构：`hdr+reserved+endian+globalNum+nFields` |

## 五、一句话总结

> **照官方定义对齐字段，照真机复刻写法，拿不到的数据就留空。**
