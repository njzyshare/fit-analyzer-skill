# 规范驱动互转（铁律 #12–#27,#29）

12. 换设备只学规范不改代码；流程为 学模板（本地不入库）→ 定规范（入库）→ 用（工具读规范）。
13. 类型码查 `base_type` 非 `type`：结构对错看 base_type，语义看 type；两家类型码与官方一致，0 偏离。
14. 渐进式布局两家都有（高驰 6 种 / 佳明 3 种），复刻节奏才能让解析器正确判断字段出现时刻。
15. dev16（Effort Pace）是平滑未量化速度近似，非等值；禁断言等值/反推 speed；缺失按 `dev_semantics` 重建（标 approx）或留哨兵。
16. 哨兵 vs 省略：模板字段源有但无值→写官方哨兵；模板整条消息源没有→省略；源有产物丢→FAIL。
17. 门禁会出错：校验不过先怀疑检查器，用 SDK 解析/原始字节裁定，别急改产物。
18. SDK 是验证工具非转换引擎：按佳明 profile 编码，禁跨品牌转高驰；仅用于导出 profile + 交叉验证。
19. 跨品牌比对前先判两端是否都声明该字段；按索引硬对会把渐进布局的结构差异误读成数据丢失。
20. 门禁 PASS 但第三方比对报差异：先排「产物错 / 门禁错 / 比较口径错」三者，别急改产物。
21. 布局一致 ≠ 值完整：结构校验与内容校验两维度都必须有；门禁 PASS ≠ 与真机一致，交付前穷举比对；fileId.productName 等身份/名称字段须值级核对。
22. 改文档用 Edit/Write，禁 `python -c`/`echo` 拼接含反引号/$/引号的文本（shell 会劫持）。
23. 门禁 PASS ≠ 交付完成；交付前穷举比对 + 三条硬规矩（差异逐项解释 / 先说清别抹平 / 过程跑通≠结果正确）。
24. 比对工具自身会撒谎：布局比对用 `tuple` 非生成器；条数守恒范围限 fileId/session/lap/record/event/activity，deviceInfo 单独 INFO；工具须回归测试。
25. 校验工具须双向回归：正确样本 EXIT=0 + 转换器层打补丁漏写字段样本 EXIT=1；禁手工改字节造 bug 样本（会漏报）。
26. 规范入库，模板不入库：规范含文件头参数/消息白名单与顺序/布局与渐进节奏/字段官方名/开发者字段声明/语义推断，不含私人数据；工具读规范缺失回退模板。
27. 精炼规范省体积省出 bug：单布局也须保留 `layout_rhythm`（补 `[[0,大数]]`）；developerDataId(207) 必收；applicationId 留 hex（前导零有意义）；判据——删后工具仍能 md5 一致才许删。
29. 以官方 profile 为唯一事实源：每次修改/创建 FIT，字段名/类型码/scale/offset/单位一律查 `references/fit_profile_official.json`（辅以 `fit_format_spec.md`），禁止凭记忆或猜测字段含义；官方 profile 无定义的字段按未知/开发者字段处理，不得臆造语义。
