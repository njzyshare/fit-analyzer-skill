# 高驰（COROS）MCP 数据采集

高驰官方 MCP 服务，走 **HTTP 流式传输**，无需 API Key。

## 一、部署配置

配置文件：`~/.workbuddy/mcp.json`（注意：**不是** `.mcp.json`）

```json
{
  "mcpServers": {
    "coros-mcp": {
      "url": "https://mcp.coros.com/mcp",
      "transport": "http-stream",
      "disabled": false
    }
  }
}
```

写入后**不会自动激活**。需到连接器管理页右上角的「自定义连接器」入口，点击「信任」该 server。

## 二、能力边界

约 40 个接口，分四类：

| 类别 | 主要接口 |
|---|---|
| **运动与训练** | 运动记录（可按日期/距离/时长/配速/地点筛）、活动详情、分段数据、训练负荷评估、恢复状态、体能评估总览 |
| **健康与身体** | 睡眠概览、睡眠 HRV、静息心率、平均心率（含时序）、每日健康数据、压力等级与时序 |
| **设备与文件** | 设备列表、用户信息、活动 FIT 下载链接、活动 FIT 下载、路线文件上传 |
| **训练计划（可写）** | 计划库/详情、日程查询、创建/更新训练计划与课程、排期 |

## 三、🔴 关键限制：取不到活动级设备型号

`getActivityDetail` 的返回字段是**固定的**：时长、距离、配速、心率、步频、触地时间、
垂直振幅、步幅、功率、爬升、卡路里、训练负荷、有氧/无氧 TE、训练焦点、Performance。

**没有任何设备字段。** `queryDevices` 只能列出账号绑定的设备，无法关联到单条活动。

→ **「某条活动是哪台表跑的」这个问题，MCP 答不了，只能读 FIT 的 `device_info`。**

## 四、数据口径要点

| 项 | 规则 |
|---|---|
| 睡眠归属 | 按**醒来日**归属。某夜的睡眠记在 D+1。问「昨晚」→ 传**今天**的日期 |
| 运动类型码 | 必须传数字码，不能传名称。跑步 `[100 户外, 101 室内, 102 越野, 103 操场]` |
| 日期格式 | `yyyyMMdd`。不传区间默认最近 7 天 |
| FIT 下载额度 | 有**每日限额**，URL 方式与二进制方式共用同一额度 |
| 力量训练动作名 | 返回英文；仍是 `T1275` 这类代号说明字典缺失，**不要猜** |

## 五、常用调用

```python
# 最近 7 天跑步
querySportRecords(sportTypeCodes=[100,101,102,103], limit=20)

# 单条活动详情（含 Best Kilometer 字段）
getActivityDetail(labelId="...", sportType=100)

# 拿原始 FIT（用于本地结构分析）—— 返回 URL，curl 下载比二进制方式更省上下文
queryActivityFitFileDownloadUrls(labelId="...", sportType=100)
```

⚠️ 批量取数时：详情接口一次只能取一条，几十条要分多轮。
**优先用 FIT 下载 + 本地解析**，比逐条调详情高效得多。

## 六、与换皮任务的关系

MCP 只负责**取数**，不参与改文件。但两处配合要点：

1. **取原始 FIT 做诊断**：判断某条活动能否算出最快1KM，需要下载 FIT 看 record 结构
   （消息种类数、`unknown_*` 数量、渐进布局种类），见 `coros_specifics.md` §九。
2. **验证上传结果**：改完上传后，用 `getActivityDetail` 看是否返回 `Best Kilometer` 字段
   —— 这是判断换皮是否成功的**唯一**验证口径。设备型号、等强配速不在这个接口里体现（本来也不显示）。
